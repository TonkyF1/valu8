## Prompt text (copy from here)

Goal: record what really happened to cars people check, so we can measure accuracy. Small, safe changes only. Don't change any pricing logic, `analyse-vehicle`, `_shared/priceModel*`, `motSignals` or `ensemble`. Don't touch deno.lock.

1. **Migration** (RLS on, no personal data, no IP, no location/postcode):
   - `advert_checks`: id uuid pk, user_id uuid null → auth.users on delete cascade, guest_token_hash text null, created_at, make, model, variant, year int, mileage int, asking_price int, seller_type text check in ('dealer','private','unknown') default 'unknown', link_url text null (strip query string and fragment), link_domain text null, link_fetchable bool default false, verdict text, estimate_private int, estimate_dealer_low/mid/high int, pricing_source text, confidence text, engine_version text, followup_sent_at, followup_answered_at, recheck_count int default 0, last_rechecked_at, last_seen_price int, listing_status text default 'unknown' ('live','gone','unknown').
   - `check_outcomes`: id, kind ('advert','valuation'), item_id uuid, source ('user','recheck'), outcome_type ('bought','not_bought','still_looking','sold','not_selling','withdrawn','price_changed'), outcome_price int null check > 0, outcome_date date null, seller_type text null, recorded_at default now(). Unique (kind, item_id) where source='user'.
   - RLS: owners select/update their own `advert_checks` and insert/update their own user outcomes; admins read all; service role writes everything else. Guests have no direct access (edge functions only, same token-hash model as guest valuations; `claim-guest-valuations` should also claim guest advert checks).
2. **fair-price**: after the result is computed (no logic change), insert an `advert_checks` row with the inputs, the band shown and `engine_version`, and return `checkId`. Set `link_fetchable = true` only if the link's domain is NOT on this denylist (and subdomains): autotrader.co.uk, pistonheads.com, motors.co.uk, cargurus.co.uk, ebay.co.uk, ebay.com, facebook.com, fb.com, gumtree.com, carwow.co.uk, heycar.com, cinch.co.uk, cazoo.co.uk, exchangeandmart.co.uk. Logging failure must never break the check.
3. **Check page**: add an optional "Who's selling?" (Dealer / Private / Not sure) field. Under the result: "We'll ask you later whether you bought it — it helps us keep our prices honest." Guests: keep check ids in localStorage like guest valuations.
4. **Follow-up (in-app only, no emails)**: 7+ days after a check, show a small card on Dashboard (and on /check for guests): "Did you buy the {year} {make} {model}?" → Bought it (price paid, optional date) / Didn't buy / Still looking (ask again in 14 days, max 3 times). Stamp `followup_sent_at` when first shown, `followup_answered_at` on answer. For valuations keep the existing "Sold it?" card; add "Not selling" and stamp `report.followupSentAt` / `report.followupDeclined`.
5. **Re-check job** (`recheck-adverts` edge function, daily pg_cron): only rows with `link_fetchable`, aged 7–60 days, `recheck_count < 4`, not rechecked in 7 days, max 50 per run, max 1 request per domain per run. Before fetching, read and obey that domain's robots.txt for user-agent `Valu8Bot` (fall back to `*`), honour Crawl-delay; skip if disallowed or robots can't be read. GET with UA `Valu8Bot/1.0 (+https://valu8.uk/bot)`, 10s timeout. Store only: listing_status (404/410 → gone), price from JSON-LD `offers.price` or `og:price:amount` if present, `last_rechecked_at`. Never store page content, seller names, phone numbers or locations. Write a `check_outcomes` row (source 'recheck', 'withdrawn' or 'price_changed'). Never fetch denylisted domains — outcomes for those come only from the user follow-up. Add a tiny `/bot` page explaining the bot and how to contact hello@valu8.uk to opt out.
6. **Readiness logging**: implement the `readiness_outcomes` view and admin-only `readiness_stats(p_engine)` RPC exactly as in `docs/monetisation/readiness.md` (include the buyer-side union), and an Admin "Readiness" tab showing: READY/NOT READY banner, gates (≥200 outcomes on £5–20k estimates, median abs error ≤12%, <5% misses over 30%), weekly progress to 200, breakdown table, follow-up funnel. No regs, user ids or emails on that tab.
7. **Privacy page**: add one paragraph: we keep the adverts you check (car details, price, link) and any outcome you tell us, to measure accuracy; no location; deleted when you delete your account. Make sure `delete-account` removes them.

Acceptance: an advert check still works if logging fails; a guest and a signed-in user can each answer a follow-up; denylisted links are never fetched; the Readiness tab loads for admins only.
